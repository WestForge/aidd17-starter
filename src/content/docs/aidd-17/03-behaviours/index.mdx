# 03 Behaviours

Define what users and the system do.

Behaviours should be clear enough to drive implementation and verification.

## Guidance

Use behaviour IDs such as `B-001`.

A behaviour should describe observable system behaviour.

## Template

```md
# B-000 Behaviour Name

## Statement

A user can ...

## Trigger

What starts the behaviour.

## Preconditions

What must already be true.

## Flow

1. Step one.
2. Step two.
3. Step three.

## Outcome

What must be true after the behaviour completes.

## Failure cases

What can fail and what must happen.

## Verification

How this behaviour is verified.
```
