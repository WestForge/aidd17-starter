<Aside type="tip" title="What this template is for">
**This template describes the whole system.** Use it once per project to define intent, architecture, rules, delivery approach, and verification. For one bounded unit of work inside that project, use the [Implementation Slice Template](/implementation-slice-template/) instead.
</Aside>

The 17 sections are grouped by the [five-part model](/structure/): **Intent**, **Shape**, **Rules**, **Delivery**, and **Verification**. Fill in each section, or jump to the [full blank template](#copyable-blank-template) at the bottom.

## Intent

*Sections 01–05 — what the product must achieve, for whom, and what success looks like.*

### 01 Purpose

Define why this project exists.

Include:

- problem being solved
- desired outcome
- business or user value
- definition of success

```md
## 01 Purpose

Project name:
Problem:
Desired outcome:
Business or user value:
Definition of success:
```

### 02 Users

Define who uses the system.

Include:

- user types
- responsibilities
- permissions
- goals

```md
## 02 Users

### User type

Name:
Description:
Goals:
Responsibilities:
Permissions:
```

### 03 Behaviours

Define what users and the system do. Use clear behaviour statements.

Example:

- A user can create or paste a text document.
- The system validates the document content and size.
- The system stores the document record.
- The system shows save success or failure.

```md
## 03 Behaviours

### Behaviour ID

Name:
User:
Trigger:
System behaviour:
Expected result:
```

### 04 Features

Define the features that support the behaviours. Each feature should map to one or more behaviours.

```md

Included:
Not included:
```

Define what must be true for the project to be successful. Use measurable criteria where possible.

```md
## 05 Success Criteria

Statement:
Measurement:
Target:
Linked behaviours or features:
```
