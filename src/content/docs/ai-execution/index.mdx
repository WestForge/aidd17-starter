AIDD-17 is not only a documentation structure. It is a delivery control system for AI-assisted work.

The project definition remains the source of truth. AI execution turns that source into smaller, safer payloads that tell an implementation agent what to read, what to change, what not to change, how to stop, and how completion will be judged.

## Why this exists

AI agents waste time and credits when they have to infer the world from a whole documentation site. They may load too much context, miss the authoritative rule, or implement a nearby feature that was never requested.

AIDD-17 avoids that by packaging work into bounded execution slices and generated bundles.

## Execution flow

1. Define or update an implementation slice.
2. Run the AIDD bundle checker.
3. Generate an execution bundle for the slice.
4. Give the bundle to the implementation agent.
5. Review the result against the acceptance criteria and AI Execution Contract.

## Local commands

```bash
npm run aidd:check
npm run aidd:bundle -- IMP-001
npm run aidd:bundle -- --all
```

Bundles are generated into:

```text
dist/aidd-bundles/
```
