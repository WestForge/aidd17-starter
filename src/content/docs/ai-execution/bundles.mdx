<Aside type="tip" title="Source of truth">
The implementation slice is the source of truth. The bundle is a generated execution payload. Regenerate the bundle whenever the source slice changes.
</Aside>

## What is an execution bundle?

An execution bundle is a small folder generated from one implementation slice. It extracts the parts an AI agent or reviewer needs most often and places them in a predictable read order.

Example output:

```text
dist/aidd-bundles/IMP-001/
  README.md
  manifest.json
  source.md
  brief.md
  scope.md
  files.md
  acceptance.md
  constraints.md
  context.md
  prompt.md
  review-prompt.md
  handoff.md
```

## Commands

Validate the project and slice templates:

```bash
npm run aidd:check
```

Generate a bundle for one slice:

```bash
npm run aidd:bundle -- IMP-001
```

Generate bundles for every concrete slice:

```bash
npm run aidd:bundle -- --all
```

Fail bundle generation if a slice is missing required headings:

```bash
npm run aidd:bundle -- IMP-001 --strict
```

## Required slice sections

The checker expects implementation slices to include these sections:

- Purpose
- Scope
- Out of Scope
- Expected Files or Areas to Change
- Files or Areas Not to Change
- Verification
- Acceptance Criteria
- AI Execution Contract
- Context Loading Order
- Stop Conditions

The templates also include prompt sections:

- Codex Prompt
- Review Prompt

## Bundle files

### `brief.md`

The high-level execution brief. This includes purpose, linked intent, linked shape, and applicable rules.

### `scope.md`

The work boundary. This includes what is in scope and what is explicitly out of scope.

### `files.md`

The expected file boundaries. This helps prevent broad refactors and unrelated edits.

### `acceptance.md`

The verification payload. Reviewers and agents use this to decide whether the work is complete.

### `constraints.md`

The AI Execution Contract and stop conditions.

### `context.md`

The context loading order. This tells agents what to read first and what not to load unless needed.

### `prompt.md`

A ready-to-use implementation prompt.

### `review-prompt.md`

A ready-to-use review prompt.

### `handoff.md`

Review notes or handoff instructions extracted from the slice.

### `manifest.json`

Machine-readable metadata for the generated bundle, including the source slice, generated time, output path, required headings, and any missing headings.

## Design rule

The documentation is authoritative. The bundle is disposable.

Do not edit generated bundle files as the source of truth. Update the implementation slice, then regenerate the bundle.
